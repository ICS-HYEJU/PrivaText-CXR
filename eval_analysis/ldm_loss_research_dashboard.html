Noise Over Signal

Two new loss levers were added to the DP-SGD LDM fine-tune — both implemented correctly, both verified free of extra privacy-budget cost. A 4-seed replication now confirms, decisively, that at pilot scale the loss function’s effect on the trained model is indistinguishable from noise.

decisive null result

What this means

It isn’t a bug in the implementation. Both smoke tests and the pilot ran cleanly under real Opacus DP-SGD wrapping; the classifier-guidance loss correctly gates itself to low-noise timesteps, and privacy accounting is verified byte-identical with the new terms on or off.

It’s a training-scale problem. At max_grad_norm=0.001 and only ~1,858 images × 8 epochs (~14,864 physical per-sample steps), the DP noise injected into every gradient step is large enough that the loss function’s influence on where training ends up doesn’t survive into the final weights — under either seed tested. set_seed() also fixes the RNG that Opacus’s own noise draws from, which is worth knowing on its own, but the seed=43 re-run shows the deeper issue is the noise-to-signal ratio itself, not merely two runs sharing a seed.

The 4-seed replication makes it decisive, not just suggestive. Across seeds 42, 43, 44, 45, the classifier-guidance+min-SNR arm never beats baseline by more than seed-to-seed noise already does within a single arm — the mean delta is 8% the size of baseline’s own seed-to-seed standard deviation, and its sign flips between seeds 44 and 45. At pilot scale, the answer is now no: neither loss term produces a detectable effect, full stop.

The production-scale question is still open, and pilot-scale seeds can’t close it. The noise floor here is set by training volume, clip norm, and epsilon — not by which seed is drawn — so running more seeds at this same pilot scale would keep probing the same noise-dominated regime. The only way to test whether these loss terms matter once there’s enough accumulated signal to plausibly clear that floor is the full ~49,907-image production scale (multi-day GPU cost, matching this repo’s other full-scale training rounds) — not launched this session.

Worth flagging for future work on this repo: other single-seed DP-SGD comparisons already recorded here (the ablation_blocks sweep, eps1-vs-eps10, epochs=10-vs-30) compare more structurally different configs — different epsilon changes the noise multiplier itself, different block counts change the trainable-parameter count — so they likely sit above this noise floor. But any small-effect-size single-seed DP-SGD comparison deserves the same scrutiny this one got.
